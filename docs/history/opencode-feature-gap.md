# 和 OpenCode 相比还缺什么

本文固化自 2026-09-30 的功能差距评估，描述的是对照当时的 Orange Code。当时已有工具循环、四个内置工具、一个 stdio MCP 客户端。下面是它当时还没有、而 OpenCode 公开产品里已经作为主路径的能力。

## 结论

差在改真实仓库时的可靠性。闭环已经能跑。缺的是搜索、局部修改、改完把错误送回模型，以及长任务不把上下文撑爆。终端界面和多提供商是产品层，不决定一次小改动能不能做完。

## 先影响改代码的部分

来源：当时的 `agent.py`、`tools.py`、`mcp_client.py`；OpenCode 公开说明（终端界面、LSP、多会话、Plan/Build、MCP 文档）。

| 能力 | OpenCode | 当时的实现 | 优先级 |
| --- | --- | --- | --- |
| 增量编辑 | 按片段替换或打补丁，保留文件其余部分 | write_file 整文件覆盖 | 先补 |
| 代码搜索 | grep 与按文件名查找，再决定读哪一段 | 只有 list_files 和整文件 read_file | 先补 |
| 改完自检 | LSP 诊断或测试输出写回下一轮 | 改完即停，编译错误不会自动送回 | 先补 |
| 上下文延续 | 会话压缩，长任务不把全文一直塞进请求 | 进程内消息列表，AGENTS.md 截到 6000 字，默认 8 步 | 先补 |
| 撤销 | 每次修改做 git 快照，可 undo | 直接写盘，没有快照 | 其次 |
| 计划再动手 | Plan 模式只读，确认后再改文件 | 一上来就能写文件和跑命令 | 其次 |

## 产品层，主流 agent 都有

| 方面 | OpenCode | 当时的实现 |
| --- | --- | --- |
| 会话 | 本地保存、继续、分叉、分享链接 | 退出进程后对话消失 |
| MCP | 多个本地或远程服务，含 OAuth，可按 agent 开关 | 一个 stdio 命令，工具名加 mcp_ 前缀 |
| 模型 | 七十多家提供商，会话中途切换 | 一个 OpenAI 兼容地址，环境变量选定 |
| 权限 | 按工具和路径 allow / ask / deny | 工作区边界，外加可选的 shell 确认 |
| 界面 | 终端界面、桌面和 IDE，流式看到工具过程 | 纯文本 CLI，单次任务只打印最终回答 |
| 扩展 | 自定义 agent、命令、子任务 | 一份系统提示，没有子 agent |

## 已经对齐的最小集

读文件、写文件、列目录、跑命令，以及把一个 stdio MCP 服务的工具并进同一次对话。本地 Ollama 和外部网关走同一套 `/v1` 接口。文件操作限制在当前工作目录。当时的工具面是 4 个内置工具加 MCP。
