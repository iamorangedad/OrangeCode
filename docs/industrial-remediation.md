# 工业级整改方案

本文固化自 2026-10-29 的源码审阅，描述的是当时仓库里的 Orange Code。当时已有工具循环、六个内置工具、一个 stdio MCP 客户端，单元测试 28 项通过。版本号是 `0.2.0`。

## 结论

最小闭环已经能跑。还不能交给真实仓库。阻断有四处：shell 能走出工作区，MCP 可能卡死，中断会弄坏对话，密钥文件会被读进模型请求。做不完真实任务，是因为改完不验证，以及长对话会撑爆上下文。

整改保持 `agent.py`、`llm.py`、`tools.py`、`mcp_client.py`、`orangecode.py` 这条循环。新能力加在循环旁边。2026-01 删掉的调度器、RAG 和技能矩阵不恢复。

多个 MCP、Plan 只读模式、按路径授权、流式界面、子 agent、操作系统级沙箱，放到下面四步有测试守住之后。

## 工业级在这里指什么

一次仓库内的小改动能做完，并且默认行为可预期：

- 文件工具停在工作区内，密钥文件不进入模型请求
- shell 在单次任务里默认不执行，交互时默认先确认
- MCP 无响应时在超时内返回错误
- 中断之后，消息序列仍然是合法的 tool 调用
- 本轮改过文件、并且配置了检查命令时，失败输出会回到模型
- 发出去的历史低于字符预算；进程重启后能恢复会话
- 最近一次任务的写入可以 undo
- 单次任务能在 stderr 看到工具轨迹

shell 加上确认和路径拒绝之后，仍然不是沙箱。文档需要写明这一点。

## 问题

来源：2026-10-29 的 `agent.py`、`tools.py`、`mcp_client.py`、`orangecode.py`，以及当时的测试。

### 阻断

| 问题 | 位置 | 后果 |
| --- | --- | --- |
| Shell 不受工作区约束 | `tools.py` 的 `execute_shell` 使用 `shell=True`，只把工作目录设在仓库内 | 模型或被注入的提示可以读、改仓库外的文件。`CONFIRM_SHELL` 默认关闭 |
| MCP 可能永久卡住 | `mcp_client.py` 把 stderr 送进管道却不读，读响应没有超时 | stderr 写满后父子进程互相等待。服务无响应时这一步不会结束，`MAX_STEPS` 管不到 |
| 中断留下坏对话 | `agent.py` 先写入带 `tool_calls` 的助手消息，再执行工具 | Ctrl-C 落在工具执行中途时，下一轮请求缺少对应的 tool 结果 |
| 密钥文件进入模型请求 | `search` / `read_file` 只跳过 `.git`、`__pycache__`、`.venv`、`node_modules` | `.env` 和密钥文件会被搜索、读取，并随消息发给模型 |

写入使用 `Path.write_text`，进程在写入中途退出时可能留下半个文件。这和上面的中断问题放在同一步修。

### 做不完真实任务

| 缺口 | 现状 | 整改落点 |
| --- | --- | --- |
| 改完不自检 | 写文件之后，循环等模型自己想起跑命令 | 模型准备结束、且本轮有写入、并配置了检查命令时，自动跑一次。失败则把输出送回，并继续循环 |
| 上下文只增不减 | `AGENTS.md` 截到 6000 字，单次工具输出截到 2 万字符，消息列表不裁 | 发请求前丢掉最早的工具正文，保留路径和成败 |
| 大文件一次读完 | `read_file` 不传行号就返回全文 | 超过行数上限时拒绝，要求先 `search` 再按行读 |
| 不能恢复 | 退出进程后对话消失，写入没有快照 | 会话落盘。第一次写入前复制原文件，提供 undo |

默认模型 `qwen2.5-coder:3b` 的上下文大约 32K token。几次整文件读取就会塞满窗口。

| 项 | 现状 |
| --- | --- |
| 持续集成 | 没有工作流，测试只在本地 `pytest` |
| 任务评测 | 模型用脚本替身。没有「改一个函数再跑检查」的场景 |

## 四步整改

每一步都接在现有循环上。默认决定如下，开发计划按这些决定拆任务。

### 1. 不越界、不卡死

Shell 使用一个策略，取值为 `ask`、`allow`、`deny`：

| 场景 | 未设置 `SHELL` 时 | 覆盖方式 |
| --- | --- | --- |
| 交互 | `ask`，执行前确认 | `SHELL=allow` 跳过确认；`SHELL=deny` 拒绝 |
| 单次任务 | `deny`，工具返回错误，不执行 | `SHELL=allow` 才执行。单次任务不出现确认提示 |

已有的 `CONFIRM_SHELL=1` 视为 `ask`，`CONFIRM_SHELL=0` 视为 `allow`。两者同时设置时，以 `SHELL` 为准。无终端的 `ask` 按 `deny` 处理，并在错误文本里说明需要 `SHELL=allow`。

文件工具拒绝这些路径：`.env`、`.env.*`、`.netrc`、`id_rsa`、`id_dsa`、`credentials.json`，以及后缀 `.pem`、`.key`、`.p12`、`.pfx`。路径任一段是 `.git` 或 `.orangecode` 时同样拒绝。`search` 跳过它们，`read_file`、`write_file`、`edit_file` 返回错误文本。

`write_file` 和 `edit_file` 先写到同一目录的临时文件，再替换目标。

MCP 读响应的默认超时是 30 秒，可用 `MCP_TIMEOUT` 调整，上限 120 秒。超时返回错误文本并结束这一次调用。stderr 由单独的读取排空，避免管道写满。

`Agent.run` 在工具执行中收到中断时，为尚未写回的 tool call 补上 `Error: interrupted`，再返回 `Interrupted.`。消息序列保持合法。

### 2. 改完自检

循环记下本轮用户请求里 `write_file` 或 `edit_file` 成功写过的路径。

`CHECK_COMMAND` 非空，且模型这一步不再调用工具、本轮确实写过文件时，用该命令在工作区执行一次。这是用户配置，不走 shell 确认。超时 120 秒。

退出码为 0 时，把模型的最终文本返回给用户。退出码非 0 时，先记下模型刚才的回答，再追加一条 user 消息，内容是命令、退出码和输出，然后继续循环。这一次继续占用 `MAX_STEPS` 里的一步。检查命令本身的输出也受 2 万字符限制。

`read_file` 在未给行号、且文件超过 400 行时，不返回正文，只返回行数和要求按行读取的错误。调用方传了 `start_line` 或 `end_line` 时仍按现有范围读取，范围结果继续受 2 万字符限制。

### 3. 长任务可恢复

每次 `chat` 之前，把非 system 消息压到字符预算内。预算默认 24000，可用 `MESSAGE_CHAR_BUDGET` 调整。先替换最早的 tool 正文为占位，占位里留下原始字符数。仍超出时，再缩短最早的 user 和 assistant 正文。system 提示和最后一条 user 消息保留。

会话写到 `.orangecode/sessions/<id>.jsonl`。交互和单次任务都写入。CLI 提供恢复入口：`python3 orangecode.py --resume <id>`，交互里也可以输入 `resume` 恢复最近一次。`.orangecode/` 不进 git。

### 4. 可撤销、可观测、可配置

一次用户请求里，某个已存在文件第一次被 `write_file` 或 `edit_file` 改动前，把原字节拷到 `.orangecode/snapshots/<turn-id>/`。新文件在清单里记为创建。`undo` 按最近一次请求恢复：已存在的文件写回原内容，本次新建的文件删除。undo 不创建 git commit。

工具开始和结束时向 stderr 打一行：工具名、关键参数、结果长度或错误。stdout 仍只放最终回答。`TRACE=0` 关闭这些行。

工作区根目录的 `orangecode.toml` 可写 `model`、`base_url`、`max_steps`、`check_command`、`shell`、`mcp_command`。环境变量覆盖文件。API key 只来自环境变量，不写入这个文件。
